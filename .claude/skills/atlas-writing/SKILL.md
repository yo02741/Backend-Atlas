# 本站寫作規則

先套用 `stop-slop` 的精神（直接、具體、信任讀者），再依本檔處理中文與介面文字。兩者衝突時以本檔為準。

## 一、介面文字：標題與元件說自己做什麼

1. **標題、按鈕、連結用名詞或動詞短語直接說它是什麼、做什麼**：「混合複習」「開始（10 題）」「重設資料庫」「全部 30 個 →」。
2. **不在元件旁邊解釋元件怎麼用**：不寫「點站名進入該課」「可以按上方的『標記完成』把這一站點亮」「先在模擬器裡看…再…最後…」。能點的東西要靠樣式看得出能點。
3. **頁首只放 kicker 與標題**。副標（lede）只在使用者不知道就會出錯或吃驚時保留，限一句：資料只存在瀏覽器、第一次會下載 13 MB、程式碼不會送到伺服器。
4. **不重複畫面上已經看得到的東西**：統計數字、清單項目、旁邊卡片的內容，不在說明文字裡再講一次。
5. **空狀態與停用原因寫一句，說怎麼解決**：「還沒有完成的課」。
6. **同一個東西只描述一次**：例如領域的簡介，卡片與領域頁不要各寫一段不同的。

## 二、課文與題目：中文的 AI 腔

| 改掉 | 改成 |
|---|---|
| 破折號 `——` 當停頓或揭曉 | 逗號、句號、冒號或括號 |
| 「不是 X，而是 Y」「X 不是問題，Y 才是」 | 直接說 Y。只有讀者普遍誤會 X 時才保留，一課最多一次 |
| 預告句：「關鍵在於：」「重點是」「答案是」「這就是為什麼」「值得注意的是」「簡單來說」「換句話說」「說穿了」 | 刪掉預告，直接寫內容 |
| 加強語氣：「其實」「真的」「真正的」「非常」「就是」（不帶資訊時） | 刪。「真正的 LRU」這種區分近似與精確的用法保留 |
| 整句加粗、一段好幾處粗體 | 一段最多一處，只標名詞或結論 |
| 段落以金句收尾、「這才是 X」 | 刪掉最後那句，或改成具體的下一步 |
| 擬人：「資料告訴我們」「決策浮現」 | 寫出誰做了什麼 |
| 空泛的重要性：「影響很大」「風險很高」 | 寫出具體影響：哪個請求失敗、多少筆資料 |

## 三、不要照搬的 stop-slop 規則

中文技術文件照搬下列規則會變得不準確，**不要**套用：

- 刪掉所有副詞：「通常」「預設」「多數情況」「至少」是準確度的一部分，保留。
- 禁止被動語態：「連線被關閉」「請求被拒絕」在技術描述裡比硬找主詞清楚。
- 列舉不准三項、句子不准用疑問詞開頭。

## 四、不動的東西

程式碼、程式題的解答與測試、選擇題的正解索引、數字、連結網址、指令與參數名稱。程式碼註解裡的破折號可以改，但不改註解的意思。

## 五、沿用的既有規則

- 不寫「為什麼要學」「為什麼重要」段落；不用「給前端工程師」「你工作上」「你已經會」。
- 不確定的事寫明不確定；不捏造連結、版本、價格、法規條文。

## 自我檢查

改完一段後問：刪掉這句，讀者會少知道什麼？答不出來就刪。
