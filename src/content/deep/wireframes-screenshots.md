## 從一個具體問題開始：照截圖做出來，「看起來一樣」

門診系統要把舊版的「今日門診」頁改寫成 Vue。工程師截了一張舊系統的畫面給 AI，附一句「照這個畫面用 Vue 3 做」。產出在 1280px 的螢幕上看起來幾乎一樣，驗收時才發現：

- 顏色是 `#2f6fe4`、`#e8eef9` 這類從像素估出來的值，和專案的 `--color-primary` 差一點點，深色主題完全沒有。
- 截圖裡的表格有 8 筆資料，產出只做了有資料的樣子：沒有載入中、沒有「今天沒有預約」、沒有錯誤畫面。
- 截圖裡的診間 Tabs 被做成一排普通按鈕，切換時網址不變，重新整理就回到第一個診間。
- 手機上表格被壓成好幾行字疊在一起。
- 截圖裡有 8 位病患的真實姓名與病歷號，整張圖已經傳到外部的 AI 服務。

截圖準確地傳達了它拍到的東西：某一個寬度、某一組資料、某一個瞬間的外觀。其他的都要另外講。

## 運作原理

### 一張截圖帶了什麼、沒帶什麼

| 截圖傳達得了 | 截圖傳達不了 |
|---|---|
| 區域的排列與相對大小 | 其他寬度下怎麼排 |
| 元件的大概長相 | 元件的名稱與種類（Tabs 還是一排按鈕？Select 還是 Combobox？） |
| 顏色、字級、間距的「感覺」 | 確切的值與對應的 token |
| 這一組資料的樣子 | 欄位名稱、資料從哪個 API 來、最長的資料會怎樣 |
| 一個狀態 | loading、empty、error、hover、focus、disabled |
| | 點了之後發生什麼、送出什麼請求、焦點移到哪 |
| | 鍵盤操作與螢幕閱讀器讀到什麼 |

左欄是外觀，右欄是行為與規格。只給截圖，右欄全部交給產出自己決定。[把畫面描述成文字](#/skill/describe-ui) 的五段式描述就是用來補右欄的；截圖負責左欄，兩者一起給。

### 標註：讓截圖可以被指名

文字描述要指到截圖裡的某個東西時，「上面那排」「右邊的按鈕」常常對到兩個以上的地方。在截圖上加編號，文字照編號寫：

```text
① 日期列：顯示「11/20（四）」，左右是「前一天」「後一天」按鈕
② 診間 Tabs：101 內科、102 小兒科、103 骨科；切換時網址的 clinic 參數跟著變
③ 預約 Data table：時間、病患姓名（遮成「王○明」）、狀態 Badge、操作
④ 「新增掛號」primary 按鈕，點了開啟掛號 Dialog
```

每一個編號寫三件事：元件名稱、它有哪些狀態、互動之後發生什麼。編號用圈起來的數字或方框都可以，截圖上的標記要和文字一一對應。截圖工具多半有加標註的功能；沒有的話，用任何繪圖工具在圖上加數字就行。

### 截圖組：每個狀態、每個寬度

一個區塊有幾個狀態，就需要幾張截圖或幾段文字。一張表列出來，有截圖的打勾，沒有的用文字寫：

| 區塊 | 有資料 | 載入中 | 沒有資料 | 錯誤 | 390px |
|---|---|---|---|---|---|
| ② 診間 Tabs | 截圖 | 文字：Tabs 先顯示、內容區 Skeleton | 不適用 | 文字：Tabs 照常，內容區顯示錯誤 | 文字：可橫向捲動 |
| ③ Data table | 截圖 | 文字：5 列 Skeleton | 文字：「這個診間今天沒有預約」 | 文字：inline Alert 加「重試」 | 文字線框：改成卡片清單 |

舊系統沒有的畫面（例如手機版），用文字線框補。文字線框的寫法見 [把畫面描述成文字](#/skill/describe-ui)；它的好處是好改，也逼自己先決定區域怎麼排。

### 確切的值從哪裡來

產出從截圖推出來的顏色、間距、字級，是從像素估的：截圖經過縮放、壓縮、螢幕的色彩設定，估出來的值接近但不一致，一個畫面裡出現五種差不多的藍色。給確切的值：

| 來源 | 怎麼取 |
|---|---|
| 設計稿 | 設計工具的檢視模式（例如 Figma 的 Dev Mode）列出顏色變數、字級、間距、圓角 |
| 專案既有的 token | `src/styles/tokens.css` 這類檔案，直接把變數名稱列進描述 |
| 現有的網頁 | Chrome DevTools 的 Elements 分頁，選元素看 Styles 與 Computed：寫的是 `var(--space-4)` 還是 `16px` |

描述裡寫「顏色與間距用 `--color-*`、`--space-*`，不要從截圖量色碼」，驗收時用 Elements 分頁檢查產出有沒有照做。

### 截圖裡的個資

醫院系統的截圖幾乎一定有病患姓名、病歷號、生日、診斷。把截圖傳給外部服務之前：

- 用測試環境的假資料截圖，或用編輯工具把姓名與編號蓋掉。
- 注意角落：瀏覽器的分頁標題、網址列的查詢參數、通知、旁邊開著的視窗。
- 院內系統的主機名稱、內部網址也算不該外流的資訊。

能用文字線框與假資料描述的，就不需要真實截圖。

### 照做，還是參考

| 說法 | 產出會怎麼理解 |
|---|---|
| 「照這張截圖做」 | 版面、元件、文案都照抄，包含截圖裡碰巧出現的東西 |
| 「參考這張截圖的版面，元件用專案的元件庫」 | 只取排列，元件與樣式照專案 |
| 「參考這個網站的風格」 | 範圍模糊；可能連對方的功能、文案、品牌顏色一起做進來 |

拿其他網站的截圖當參考時，寫明要參考的是哪一部分（「表格的密度」「篩選列放在上方」），其他照專案的規範。

## 實際範例：截圖加文字

給 AI 的完整內容（截圖另外附上，圖上標了 ①～④）：

```text
附圖是舊系統的「今日門診」頁，1280px 寬、有資料的狀態，標了 ①～④。
這張圖只用來參考版面與元件的排列；元件用專案的元件庫，顏色與間距只用 --color-*、--space-* token，不要從圖上量色碼。

① 日期列：今天的日期與「前一天」「後一天」按鈕；改日期時網址的 date 參數跟著變。
② 診間 Tabs（元件庫的 Tabs）：資料來自 GET /api/clinics，切換時網址的 clinic 參數跟著變，重新整理停在同一個診間。
③ 預約 Data table：資料來自 GET /api/appointments?date=YYYY-MM-DD&clinic=…，
   回傳 [{ id, time, patientName, status }]，status 是 booked、checked_in、cancelled 之一；
   病患姓名遮成「王○明」；狀態用 Badge；操作欄只有 booked 時顯示「報到」。
④ 「新增掛號」primary 按鈕：開啟掛號 Dialog（這次不做 Dialog 內容）。

狀態（圖上沒有）：
- 載入中：② 照常顯示，③ 顯示 5 列 Skeleton。
- 沒有資料：③ 顯示「這個診間今天沒有預約」。
- 錯誤：③ 顯示 inline Alert「無法載入預約」與「重試」按鈕。

390px（圖上沒有）：
  [日期列]
  [診間 Tabs，可橫向捲動]
  [卡片：09:00 王○明 候診 [報到]]
  [卡片：09:15 陳○華 已報到]
  [新增掛號（固定在底部）]
```

這份描述的每一段都對得到一條驗收：編號對元件、狀態對畫面、390 對文字線框、token 對 Elements 分頁。

## 常見錯誤

| 現象 | 原因 | 修法 |
|---|---|---|
| 產出只有截圖裡那個狀態 | 截圖只拍到一個狀態，文字沒補 | 用狀態表列出每個區塊的每個狀態 |
| 顏色、間距是一堆接近但不一致的值 | 從截圖估出來的 | 列出 token，寫明不要從圖上量 |
| 該是 Tabs 的做成一排按鈕，該是 Combobox 的做成 Select | 截圖看得出長相，看不出元件種類 | 標註裡寫元件名稱 |
| 手機版被壓扁 | 只有桌機截圖 | 補 390 的文字線框或截圖 |
| 「上面那排按鈕」被理解成另一排 | 截圖裡有好幾個符合的地方 | 加編號標註 |
| 產出出現截圖裡碰巧有的東西（舊系統的公告、別人的 logo） | 「照這張做」 | 寫明參考的範圍 |
| 截圖裡的病患姓名傳到了外部服務 | 用了正式環境的截圖 | 用假資料截圖，或先遮蓋 |
| 截圖裡的小字被讀錯 | 解析度低或字太小 | 重要的文案用文字寫出來，不靠截圖 |

## 動手

1. 找一個自己在用的系統畫面，截圖後加上編號標註，每個編號寫元件名稱、狀態與互動；再列出這張截圖沒有拍到的狀態與寬度。
2. 用 Chrome DevTools 的 Elements 分頁，查那個畫面上三個元素的顏色與間距是寫死的值還是 CSS 變數，整理成一張 token 清單。
3. 把同一個畫面分別用「只有截圖」與「截圖加上面那樣的文字」交給 AI，用 [驗收 AI 產出的前端](#/skill/ai-acceptance) 的清單比較兩份產出。
4. 拆成元件之後再寫，見 [先拆元件再寫](#/skill/component-breakdown)。
